# 领域证据报告

当通用仓库检查不足以可靠重建某一领域时，用本契约组织取证结果。它是 YuanForge 与领域画像或未来领域 Skill 之间的接口，不是新的项目事实源。

## 所有权

- 领域画像负责发现、分类和引用证据。
- YuanForge 负责判断就绪、解决冲突并选择规范归属。
- 项目稳定文档负责保存确认后的长期事实。

除非仓库已有规范位置或用户明确要求，不把临时报告提交为独立文件。不得让领域画像直接创建第二套 PRD、流程、架构或状态文档。

## 最小报告

```text
领域：
范围：
检查模式：source-only | runtime | artifact-only | mixed

当前事实：
- <主张> — <证据位置> — confirmed | inferred

目标意图：
- <主张> — <需求、设计或用户证据> — confirmed | conflicting

候选方案：
- <尚未接受的推导或建议> — proposed

缺口与冲突：
- <当前与目标的差异，或证据互相冲突>

阻塞项：
- <一个合理答案会改变行为或验收的问题>

建议规范归属：
- <信息职责> → <现有或建议文档>

结论：READY | PARTIAL | BLOCKED
```

每项关键主张必须带可复查的文件、行、路由、测试、截图、运行结果或用户确认。`inferred` 不能静默晋升为目标意图。

## 运行规则

1. 先声明本次能检查的证据模式和缺失能力。
2. 分开当前事实、目标意图和候选方案。
3. 记录冲突，不按证据数量投票。
4. 把会改变行为或验收的未知项交给 YuanForge 就绪门槛。
5. 一次只提出一个最高价值阻塞问题。
6. 把确认结果写回唯一规范归属；临时取证过程留给任务输出和 Git 历史。

领域画像不是 YuanForge 的硬依赖，必须可独立退化。没有专用工具或运行环境时，报告 `PARTIAL` 和准确缺口，不得让 YuanForge 因缺少可选扩展而无法建立其他基线职责。
