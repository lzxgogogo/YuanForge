# 意图发现与确认

当项目是新项目，或目标意图缺失、冲突、仍在形成时使用。YuanForge 帮助意图浮现和归档，不替用户凭空决定目标。

## 区分项目状态

- **新项目：** 链接、PPT、原型、草稿和对话是目标意图素材；它们不是已有项目的当前事实。
- **已有项目：** 代码、测试、运行结果和产物证明当前实现；目标意图仍需已确认文档或用户决定支持。
- **混合项目：** 对每项主张分别标记 `current`、`confirmed`、`proposed` 或 `To confirm`。

## 让意图浮现

用户不必一开始知道完整意图。先检查已有素材，再围绕最高影响未知项循环：

1. 从情境开始：谁在什么情况下遇到什么问题？
2. 明确结果：完成后发生什么变化，用户凭什么知道成功？
3. 暴露取舍：哪些合理答案会改变范围、体验、风险或验收？
4. 提供少量候选方案、例子或低成本原型，并明确标记 `proposed`。
5. 让用户确认、拒绝或修正关键选择。
6. 把确认结果写入唯一规范位置，把未决项保留为 `To confirm`。

一次只问一个会改变行为或验收的问题。不要要求用户预先设计文件结构、页面清单或技术方案。

## 写入门槛

- 仓库可证的当前事实可以直接记录，并附证据。
- 关键取舍经用户确认后，目标可以写入稳定规范。
- Agent 推导只能作为候选方案。
- 会改变范围、公开行为、安全、数据处理或验收的未知项未解决时，不把目标文档标为完成。
- 用户明确要求早期草稿时可以生成 `PARTIAL` 草稿，但必须把未确认内容显式标记为 `To confirm`。

对 UI 等难以从实现反推目标的领域，优先确认角色、触发情境、用户目标、完成信号和关键失败责任；页面与组件只是后续表达，不是意图本身。
