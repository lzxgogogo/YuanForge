# 受控基线演化

让每个仓库形成自己的运行性格，同时防止指令静默漂移。

## 分离四个层次

| 层次 | 范围 | 变更策略 |
|---|---|---|
| Skill 内核 | 跨项目共享 | 只有多项目证据和维护者明确评审后才修改 |
| 稳定项目基线 | 仓库特有事实与偏好 | 通过有证据、可审查的 Diff 晋升 |
| Lessons | 本项目可复用的预防规则 | 在具体纠正、失败或事故后加入 |
| Progress | 当前状态和下一步 | 任务状态发生实质变化时更新 |

不得把某个项目的偏好自动写回全局 Skill。

## 观察偏好证据

可以使用以下证据：

- 用户重复纠正或评审意见；
- 代码库中已经占主导的重复实现选择；
- 已接受的架构或产品决策；
- 事故及其经过验证的根因；
- 重复出现的测试、发布或 Worktree 实践；
- 用户对项目运行方式的明确说明。

不得从单次随意风格选择、生成文件、已放弃实验或未经评审的分支中推断长期偏好。

语言也是项目偏好。明确的用户语言要求可以立即成为证据；否则根据持续维护的规范文档判断主导语言。不要因为旧文件数量更多，就让过时或自动生成的文本压过当前事实源。

## 存储前分类

把每个候选项放入唯一规范位置：

| 候选内容 | 规范归属 |
|---|---|
| 当前任务状态、阻塞、下一步 | `progress.txt` |
| 可复用的症状、根因、预防 | `lessons.md` |
| 目标、范围和成功条件 | 意图职责的规范文档 |
| 流程、状态和恢复行为 | 流程职责的规范文档 |
| 方法、工具、环境和数据来源 | 方法职责的规范文档 |
| 用户、参与者、系统或受众接口 | 交互职责的规范文档 |
| 模块、证据、数据或责任边界 | 结构职责的规范文档 |
| 交付顺序、复现或验证关卡 | 交付职责的规范文档 |
| Agent 阅读或执行规则 | `AGENTS.md` 中的精炼条目 |
| 分支和 Worktree 行为 | `docs/WORKTREE_GUIDE.md` |

已有稳定职责可以容纳事实时，不要新增通用的 `preferences.md`。

## 有意识地晋升

1. 说明观察到的模式和支持证据。
2. 区分事实、偏好、预防规则和临时变通。
3. 确定规范目标和冲突规则。
4. 提出最小的长期修改。
5. 修改未来行为、架构、安全或验收时取得用户确认。
6. 应用修改并更新受影响的链接或验证。
7. 检查 `AGENTS.md` 是否吸收了本应归属其他文档的细节。

单次高严重度事故或明确架构决策可以支持立即晋升。低影响偏好通常需要重复证据或明确表达。不得用机械出现次数替代判断。

## 审计漂移

审计基线时寻找：

- 与当前主导实现矛盾的规则；
- 应该晋升或退休的 Lessons；
- 没有进入稳定指导的重复用户纠正；
- 已经成为长期事实的 Progress 条目；
- 多个文件中重复的偏好；
- 仍在影响 Agent 的过时指令；
- 意外写入全局 Skill 的项目特有规则；
- 新文档与项目语言偏好不一致，或无理由混用语言。

用可审查的 Diff 报告建议晋升、冲突和退休项。不得静默改写项目性格。
